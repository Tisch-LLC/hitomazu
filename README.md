# ひとまず

離れて暮らす地方の実家について、何から始めればよいか分からない人のための手続きナビです。Built with Claude: Japan 2026 の提出作品として制作中です。

## 解きたい課題

親が施設に入った、親が亡くなって実家を相続した、親が一人で暮らしていて先が心配。でも自分は遠くに住んでいて、帰れるのは年に数回だけ。そんな人が「何を、いつまでに、誰に相談すればよいか」で立ち止まり、実家が放置されて「負動産」になっていくことを防ぎます。

島根県では、売りにも貸しにも出されていない空き家の割合が全国の約2倍です（2023年：全国 5.9%、島根県 11.3%。日本総合研究所「2040年代の全国・都道府県別空き家数・空き家率の推計」2025年3月）。空き家の取得経緯の約55%は相続で、所有者の約3割は1時間を超える遠方に住んでいます（国土交通省「令和元年空き家所有者実態調査」）。

## デモ動画

準備中です。

始め方は2つあります。

- **質問に答える**：ボタンを押すだけで、1問ずつ答えます。
- **自分の言葉で書く**：状況を文章で書く（スマホなら話して入力する）と、Claude が読み取って質問の答えを埋めます。読み取った項目ごとに、根拠になった文章を引用して示し、利用者が確認してから反映します。書かれていないことは推測せず、まだ答えていない質問だけをあとで聞きます。

最初の質問では、実家のいまの状況を4つから選びます。

- 持ち主は存命だが、施設などに移って空いている
- 持ち主がまだ住んでいて、将来に備えたい
- 親などが亡くなり、相続した（する予定）
- すでに自分や家族の名義で、空いている

状況に合わせて、「最低限やること」を次のグループに分けて示します。相続の手続きは、相続の場合だけ表示します。細かい条件（確定申告の有無など）は、リストの該当項目の上で「はい・いいえ」で答えられます。

- **期限があるもの**（相続の場合）：相続放棄（3か月）、準確定申告（4か月）、相続税（10か月）、相続登記（3年）、農地・森林の届出、空き家の3,000万円特別控除の売却期限
- **遠隔でできるもの**：持ち主の意向と判断能力の確認、登記事項証明書のオンライン請求、固定資産税の通知、郵便物・公共料金・火災保険など
- **次の帰省でやるもの**：書類の場所の確認、写真撮影、鍵、家財、近所への挨拶など
- **これからの方針を考える**：家族の希望の整理、建物の状態と耐震、田畑・山林の手続き、地元の相談先
- **放置しないための管理**：見回り、管理不全空家の勧告を避ける、「引き取ります」という勧誘への注意

あわせて「負動産にしないために」として、売る・貸す・解体するときに時間や費用がかかりやすい点（共有名義、相続登記がまだ、細い道、境目、田畑・山林、建物の傷み、家財など）と、早めにやることを示します。値段の判断はしません。

各項目には、国や自治体の案内ページを根拠として付け、「相談先」の種類（市町村・法務局・税務署・司法書士・税理士・弁護士など）を目印として示します。特定の事務所への紹介は行いません。各項目から「AIに質問する」を開くと、その項目について Claude に質問できます。Claude はその項目の説明・窓口・出典と利用者の状況だけを根拠に答え、使った出典と最終的な確認先を示します。法律・税金・価格の判断はしません。

不動産会社に相談するときのために、家の状態・手元の書類・相談したいことをまとめた「ご相談シート」を作れます。売主が書く物件状況報告書や付帯設備表、査定に使う書類を参考に項目を選びました。分からない項目は「分からない（確認をお願いしたい）」と示し、回答から「不動産会社に確認したいこと」を自動で作ります。ブラウザの印刷機能で、印刷またはPDF保存ができます。名前と電話番号は保存せず、印刷後に手書きします。

ネットに慣れていない人でも使えるように、文字とボタンを大きくし、操作は選択肢を押すだけにしています。

## 設計の方針

- チェックリストの中身は、出典を確認した固定データ（`src/domain/checklist.ts`）として持ちます。
- 当てはまるかどうかと期限の日付は、プログラムで計算します（`src/domain/dates.ts`）。単体テストで確かめています。
- 入力した内容は、ブラウザの中（localStorage）だけに保存します。
- このアプリは手続きの漏れを防ぐためのもので、法律・税務の判断を代わりに行うものではありません。

## 公開（Cloudflare Workers）

公開中：https://hitomazu.tanoue.workers.dev

画面は Workers の静的アセットとして配信し、`/api/` だけを Worker（`src/worker.ts`）で処理します。設定は `wrangler.toml` にあります。

```bash
bun run build                              # dist/ に画面をビルド
bunx wrangler login                        # 初回だけ。ブラウザで Cloudflare にログイン
bunx wrangler secret put ANTHROPIC_API_KEY # APIキーを secret として登録
bun run deploy                             # ビルドして公開（https://hitomazu.<アカウント名>.workers.dev）
bun run cf:dev                             # 手元で Worker として動かして確かめる
```

使いすぎ対策は三重です。Workers の Rate Limiting（同じ利用者から1分に10回まで）、KV を有効にした場合の1日の上限（`wrangler.toml` の説明を参照）、そして Claude Console のワークスペースの利用上限（金額）です。最後の金額の上限は必ず設定してください。

## Claude の出力の評価

正解を決めた例文で、Claude の出力を採点しています（実際に API を呼ぶので費用がかかります）。

```bash
bun run eval:understand  # 文章からの読み取り：正解率、推測で埋めた数、番地を含めた住所
bun run eval:ask         # 項目ごとの質問：値段・税の判断をしない、指示文を漏らさない、期限と窓口を伝える
```

2026-11-06 の結果（claude-opus-5-5）：読み取りは10件で正解率100%（36/36）、推測0件。質問は5件すべて合格。
最初の実行では、指示文を引き出そうとする質問を「範囲外」として扱わない例が1件あったため、指示を具体的にして合格を確かめました。例文は開発者が作成したもので、件数はまだ少数です。

## 構成

```text
src/index.ts                 # 手元で動かすときのサーバー（Bun）
src/worker.ts                # 公開用の Cloudflare Workers の入口
src/server/api.ts            # /api/ の処理（Bun と Workers で共通）
src/server/ask.ts            # 項目ごとの質問への回答（項目の固定データだけを根拠にする）
src/server/limits.ts         # 使いすぎを防ぐ上限（利用者ごと・1日あたり）
src/server/config.ts         # 環境変数からの Claude API の設定
src/server/understand.ts     # 文章からの読み取り（Claude の構造化出力と、結果の検証）
src/index.html, frontend.tsx # フロントエンドの入口
src/App.tsx                  # 画面全体（はじめに → 質問 → やることリスト）
src/components/              # 質問の画面、やることリスト、ご相談シート（質問と印刷用の画面）
src/domain/                  # チェックリスト・質問・ご相談シート・負動産のチェックのデータ、期限の計算、状況の型、デモ用の架空データ
src/storage.ts               # ブラウザへの保存
evals/                       # Claude の出力の評価（例文と採点のスクリプト）
CLAUDE.md                    # 開発の約束ごと（Claude Code 向け）
```

React 19、Tailwind CSS 4、TypeScript を使い、サーバーとフロントエンドを Bun の1プロセスで動かします。

## 使い方

[Bun](https://bun.com) 1.4 以降が必要です。

```bash
bun install   # 依存関係のインストール
bun dev       # 開発サーバー（ホットリロード）
bun test      # 単体テスト
bun check     # 型チェック
bun run build # dist/ へビルド
bun start     # 本番モードで起動
```

### Claude API の設定

```bash
cp .env.example .env
# .env の ANTHROPIC_API_KEY にキーを入れる（CLAUDE_MODEL は省略可、既定は claude-opus-5-5）
```

`.env` はコミットされません。キーはサーバー側だけで使い、画面には渡しません。

公開するときの使いすぎ対策として、Claude を呼べる回数に上限があります（`.env.example` の `CLAUDE_DAILY_LIMIT` など）。上限に達しても、AIを使わない機能はそのまま使えます。金額の上限は、Claude Console のワークスペースの利用上限でも設定してください。`GET /api/status` で、設定済みかどうかとモデル名だけを確認できます。
